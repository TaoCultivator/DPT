DPT 前端方案对照 · 三个可比较原型

三个原型画的是同一条波形、同一份参数值——共用 data.mjs 的数据生成、vdiv/yPosition 换算、min/max 包络降采样与参数表。 因此差异只来自技术栈与视觉语言，可直接横向比较审美上限与实现成本。
帧率口径提醒：下表「同步绘制耗时」是在无头 Chrome 中测得的单帧 CPU 成本， 不是用户体验帧率。无头模式会限频 requestAnimationFrame， 因此原型内只显示 ms/帧、不显示 FPS。真实交互帧率必须在有显示的机器上实测， 这是前端决策的未完成验证项。
原型 A · 推荐当前保留

PyQt6 精致化（现状延续）

桌面专业仪器风：近直角、细描边、高信息密度、克制动效。 在现有 pyqtgraph 栈内做视觉与交互打磨，不换技术栈。
迁移成本零
绘制成本0.40 ms/帧 · Canvas2D
风险低
前置条件先拆分 main_window.py(11 368 行)
结论：零迁移风险，但圆角/阴影/动效天花板低。 建议作为 P0 还债后的默认路线，在 P3 用真实波形实测后再决定是否升级。
原型 B · 审美上限最高

Tauri + Web 前端（WebGL 绘波）

现代设计系统：玻璃拟态、渐变层次、大留白、呼吸动效。 波形走 WebGL 顶点批量绘制，十万点级仍可保持高帧率。
迁移成本最高（重写 25 981 行 GUI）
绘制成本0.27 ms/帧 · WebGL
风险高
新增依赖WebView2 运行时
结论：审美与交互上限确实最高，但要付 WebView 依赖、打包改造、 中文排版与高分屏重新验证的代价。当前不建议立即启动； P0 完成后用真实波形实测帧率与光标手感再决策。
原型 C · 备选

egui / iced 原生 Rust

即时模式外观：小圆角、单色面板、文字按钮、几乎无阴影与动效。 单栈、无 WebView、部署最干净，外观也最朴素。
迁移成本极高（连渲染层重建）
绘制成本0.10 ms/帧 · 光栅化
风险高
待验证中文排版、高分屏
结论：审美上限明显低于 A/B。当前否决， 仅保留为「极端追求单栈/单 exe」时的备选。
