## 什么时候需要

改动**只在 DSH 启动时加载**的东西之后（插件代码、profile 的 `dsh.profile.bundles` 插件行、部分运行时常量），必须先重启 DSH 才能验证。

## 六步速查

1. **写标记**：`restart-request.json` 必须有 `expiresAt`（默认 10 分钟）与 `postRestartCheck`（写清"重启后要验什么"），缺一个脚本直接拒绝。
2. **先排续跑任务**（顺序不能反）：`schedule_create`，`after_seconds ≈ 150`，prompt 里逐字抄 `postRestartCheck`。
3. **触发**：
   ```powershell
   # 3a 总自检（防滥用 12 例 + 幂等全链路 + 红线断言：DSH 应用根进程必须没变）
   pwsh -NoProfile -File 'E:\AI图书馆\DSH-学习库\03-运行时取证\脚本\dsh-restart-verify.ps1'
   # 3b 真正触发
   pwsh -NoProfile -File 'E:\AI图书馆\DSH-学习库\03-运行时取证\脚本\dsh-restart-once.ps1' `
        -Request .\restart-request.json -DelaySeconds 45
   ```
   单脚本自检：`-DryRun`（干跑：不杀进程、不重启、不写锁、不标记 `usedAt`）；`-SelfTestSpawn`（链路实证自检：
   拉起无害探针 runner，**等它真写出日志才判定通过**，不碰 DSH、不需要标记）。**真机重启前先跑总自检**。
   `-RunnerSpawn auto|wmi|schtasks`：auto 默认走 `schtasks` 一次性任务（计划任务服务代建、自删），失败回落 `wmi`。
4. **runner**：延时 → 结束 DSH → 重新拉起 → 自清理标记/锁/启动器/自身/一次性任务，过程写 `restart-runner.log`（1/5–5/5 五步）。
5. **重启后自动续跑**：宿主启动时即重新计算日程，到点把消息投进原会话（**不需要用户打开会话**；重启窗口内到期的会补投，可能重复一次，所以 prompt 要幂等）。
   - **已有一手真机证据（2026-10-15 夜）**：19:16:26 预注册的提醒，在 19:18:09 用户自然重启之后于 20:16:26 自动投递，并在同一秒让会话自己开出新回合；21:16/22:16/23:16 重复三次。
   - 若担心**到期点正好落在停机窗口内**，叠加**通道 3**（停机播种 + 守望自动核对，路线 A2）：`dsh-restart-window-sentinel.ps1`（守望，TTL 24h，自清理，不启动/不杀/不重启 DSH）、`dsh-resume-seed.ps1`、`dsh-restart-window-check.ps1`（只读核对，判不到就 UNKNOWN）。
6. **回填结论**：写进被验证的议题；流程自身的问题回填 `k-mv8ak8zi-4`。

## 两个续跑通道

| 通道 | 机制 | 什么时候用 |
|---|---|---|
| 日程提醒（`@deepseek-ai/dsh-schedule`） | 宿主重启后 `requestDrive()` 重新计算，投递时 `resolveAgent` 恢复冷会话；**2026-10-15 夜已有一手真机证据**（重启后自动投递并自动开新回合） | **默认必排** |
| 看板自动执行（`dsh-task-board`，本工作区 `autoExec` 已开启、间隔 60s） | 重启后插件重新加载，自动派发 `todo` 议题给新的 executor | 需要**独立执行者**做代码级核验时叠加 |
| 停机播种 + 守望自动核对（路线 A2） | 停机窗口内把带 marker 的载荷写进 `schedule.json`，宿主起来必然扫到；守望在新宿主起来后自动 `-PostRestart` 核对 | **到期点可能落在停机窗口内**时叠加 |

## 红线

- 重启会**连带杀死并行议题的执行者**：动手前先确认没有别的任务在跑。
- 脚本只认白名单里的 DSH 可执行文件，不接受额外命令/参数；不做任意命令的重启后门。
- 做「替身验证」时必须断言被调用的脚本/目标落在沙箱内（D4 的教训），并在跑完后断言应用根进程未变。
- **有并行议题在跑时不要复跑全链路（替身）自检**：一旦出现 D4 类回归，代价就是真的杀掉 DSH、连坐所有执行者；这种场景改用 `-SkipFullChain`（防滥用 12 例 + 红线断言，不派生任何进程）。
- 不做常驻服务 / 常设计划任务（要的就是"临时、用完即弃"）；真机实测需**用户批准后由人执行**。
